# SABA 뉴스 수집 소스 후보

> 목적: 여러 출처에서 먼저 뉴스를 수집한 뒤 기사 내용을 분석·분류하여
> 뉴스레터 각 영역에 배치하기 위한 수집원 후보 목록.
>
> **중요:** 특정 사이트를 특정 뉴스레터 영역에 고정 매핑하지 않는다.
> 실제 채택 전 RSS/API, 이용 조건, 안정성 등을 확인한다.

## SABA 수집·분류 원칙

``` text
[수집원]
보안뉴스 / KISA / KrCERT / CISA / NVD
The Hacker News / BleepingComputer / SecurityWeek
전자신문 / ZDNet Korea
OpenAI / Google / Microsoft / Anthropic
한국은행 / KOSIS ...
        ↓
[수집]
제목 / 본문·요약 / 게시일 / 출처 / URL
        ↓
[정규화 + 중복 판단]
        ↓
[AI 분석·분류]
카테고리 / 중요도 / 관련 부서 / 요약 / 시사점 후보
        ↓
[뉴스레터 배치]
일정 / 핫이슈 / 보안시장 동향 / 보안 뉴스
기업 소식 / Tech / 경제 지표
        ↓
[중요 기사 재선별]
부서별 주요 이슈 / 보안 심층 뉴스 / AI & Tech 상세
```

### 핵심 원칙

-   `Source`와 `Category`를 분리한다.
-   사이트는 **어디에서 가져왔는가(Source)** 를 의미한다.
-   뉴스레터 영역은 **무슨 내용인가(Category)** 를 의미한다.
-   한 사이트에서 여러 카테고리의 기사가 들어올 수 있다.
-   동일 사건을 여러 출처가 보도하면 중복 기사로 그대로 나열하지 않고
    하나의 이슈로 묶는 방향을 검토한다.
-   공식 자료가 있으면 공식 출처를 우선 근거로 사용하고 관련 언론 보도를
    보조 자료로 연결하는 방향을 검토한다.
-   뉴스레터 영역별 목표 기사 수와 최종 선별 규칙은 별도 설계에서
    확정한다.

## 구현 전 수집원별 확인 항목

-   RSS 제공 여부
-   공식 API 제공 여부
-   JSON/CSV 등 구조화 데이터 제공 여부
-   크롤링 필요 여부
-   이용약관/robots 정책 확인 필요 여부
-   게시 빈도 및 예상 일일 수집량
-   본문 확보 가능 범위
-   중복 기사 발생 가능성
-   수집 안정성
-   최종 채택 여부

> 현재는 **수집 후보군 정의 단계**다. 실제 RSS/API/크롤링 연결은 수집원
> 검토와 사용자 확인 후 진행한다.
