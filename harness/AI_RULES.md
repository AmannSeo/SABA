# SABA AI RULES

Version: 1.0

## 1. 목적

이 문서는 SABA에서 사용하는 AI Provider,
Model, 비용, 외부 데이터 전송, API 호출 및
Secret 관리에 대한 공통 하네스 규칙을 정의한다.

AI 관련 설계, 구현, 테스트, 실행 및
후속 프롬프트에는 이 규칙을 적용한다.


==================================================
2. 현재 승인 상태
==================================================

현재 상태:

- AI Provider: 미확정
- AI Model: 미확정
- 유료 AI API 사용: 미승인
- 개인 비용 부담: 전제로 하지 않음
- 무료 API: 우선 검토 대상
- 회사 데이터 외부 전송 적합성: 확인 필요

과거 프롬프트나 설계 문서에
특정 Provider 또는 Model이 적혀 있다는 이유만으로
현재 승인된 것으로 간주하지 않는다.


==================================================
3. Provider 및 Model 결정
==================================================

Provider 또는 Model을 결정하기 전에
최소 다음을 확인한다.

- 무료 사용 가능 여부
- 무료 사용 한도
- 무료 초과 시 동작
- 유료 전환 조건
- 입력 Token 비용
- 출력 Token 비용
- 요청 제한
- Rate Limit
- Structured Output 지원
- 필요한 API 기능 지원
- 한국어 처리 가능성
- 데이터 이용 정책
- 회사 데이터 처리 적합성
- 상업적 사용 조건
- 운영 안정성
- Python 연동 난이도
- Secret 관리 방법

선택이 필요한 경우 사용자에게:

- 가능한 방법
- 장점
- 단점
- 비용
- 데이터 처리 조건
- 추천 방법
- 추천 이유

를 제시한다.

사용자 승인 전
Provider와 Model을 확정하지 않는다.


==================================================
4. 비용 원칙
==================================================

현재 SABA MVP는
사용자의 개인 비용 발생을 기본 전제로 하지 않는다.

사용자의 명시적 승인 없이:

- 유료 API 호출
- 결제 수단 등록을 전제로 한 구현
- 유료 요금제 활성화
- 자동 유료 전환

을 하지 않는다.

무료 API를 사용하는 경우에도:

- 무료 한도
- 호출 한도
- Token 한도
- 초과 시 동작

을 확인한다.

무료 한도 초과 시
자동으로 유료 호출로 전환하지 않는다.

비용을 확인할 수 없다면
무료라고 추정하지 않는다.


==================================================
5. 무료 API 원칙
==================================================

무료라는 이유만으로
Provider를 자동 승인하지 않는다.

최소 다음을 확인한다.

- 무료 호출량
- 무료 Token
- Rate Limit
- 무료 정책 유지 조건
- 입력 데이터 이용 정책
- 학습 또는 제품 개선 사용 여부
- 회사 데이터 처리 적합성
- 상업적 사용 조건
- 운영 환경에서 사용 가능 여부

회사 데이터 처리에 적합하지 않다면
무료라는 이유만으로 선택하지 않는다.


==================================================
6. 실제 API 호출
==================================================

실제 외부 AI API 호출은
다음이 확인된 이후에만 허용한다.

- Provider 승인
- Model 승인
- 비용 정책 승인
- 데이터 전송 범위 승인
- Secret 준비
- 호출 범위 승인

하나라도 미확정이면
실제 API 호출을 하지 않는다.

Mock 및 Fixture 테스트는
실제 API 승인 없이 수행할 수 있다.

Mock 성공을
실제 API 연결 성공으로 표현하지 않는다.


==================================================
7. 데이터 전송
==================================================

외부 AI에 전송하는 데이터는
필요한 최소 범위로 제한한다.

다음을 필요 없이 전송하지 않는다.

- 회사 내부정보
- 개인정보
- 인증정보
- Secret
- 전체 DB
- 전체 Article JSON
- 선택되지 않은 기사 원문
- 기존 분석 결과
- 불필요한 Metadata

Provider가 입력 데이터를
학습 또는 제품 개선에 사용할 수 있다면
회사 데이터 사용 적합성을 별도로 검토한다.

정책 판단이 필요하면
사용자에게 보고하고 승인을 기다린다.


==================================================
8. Secret
==================================================

다음을 Source Code에 작성하지 않는다.

- API Key
- Access Token
- Refresh Token
- Client Secret
- Password

환경변수 또는
승인된 Secret 관리 방식을 사용한다.

실제 Secret을:

- 로그
- 오류 메시지
- 테스트 Fixture
- Git
- 대화

에 출력하지 않는다.

.env를 사용할 경우
Git에 Commit하지 않는다.

.env.example에는
실제 값을 넣지 않는다.


==================================================
9. Provider 및 Model 변경
==================================================

Provider 또는 Model 변경을
단순 코드 변경으로 처리하지 않는다.

변경 전에 최소 다음 영향을 확인한다.

- 분석 품질
- 비용
- Schema 호환성
- Structured Output
- Token 제한
- 테스트
- 데이터 정책
- Rate Limit
- 운영 안정성

사용자 승인 후 변경한다.


==================================================
10. 테스트
==================================================

AI 관련 구현은
harness/ 아래의 테스트 규칙을 함께 적용한다.

최소 다음을 구분한다.

- Unit Test
- Mock
- Fixture
- 실제 API 연결
- 실제 뉴스 분석
- 사람 품질 검토

각 결과를 서로 대체하지 않는다.

실제 API 호출이 승인되지 않았다면
테스트가 실제 외부 Network를 호출하지 않아야 한다.


==================================================
11. 프롬프트 규칙
==================================================

AI 관련 단계 프롬프트는
현재 AI 승인 상태를 먼저 확인한다.

미확정 상태를
승인된 값으로 바꾸지 않는다.

다음 표현은
사용자 승인 근거가 있을 때만 사용할 수 있다.

- Provider 확정
- Model 확정
- 유료 API 사용
- 실제 API 호출
- 회사 데이터 전송

AI 관련 프롬프트는
harness/PROMPT_VALIDATION.md의
최종 출력 게이트도 통과해야 한다.


==================================================
12. 현재 상태 변경
==================================================

이 문서의 현재 승인 상태는
사용자 결정에 따라 변경할 수 있다.

변경할 때는:

- 무엇이 승인되었는지
- 무엇이 여전히 미확정인지
- 비용 영향
- 데이터 영향

을 명확하게 기록한다.

과거 프롬프트에 적힌 값만을 근거로
현재 상태를 자동 변경하지 않는다.
