# COLLABORATION RULES (Codex · Claude Code)

사용자 지시 (2026-10-16). 사용자가 매번 따로 시키지 않아도 아래 방식으로 일한다.

## 1. 역할

- Codex 세션: `01a132ba-d6c6-7591-9b63-c5b30c7f5e7f` (CLI `codex exec resume <세션> -`, 검토는 `-c sandbox_mode=read-only`, 구현은 `-c sandbox_mode=workspace-write`).
- Claude Code: 작업을 나누고 Codex 에 넘기며, Codex 결과를 다시 확인하고 사용자에게 보고한다.
- 사용자: 결정·승인·Commit. 두 에이전트 모두 Commit·브랜치 생성을 하지 않는다.

## 2. 교차 검증 (모든 개발·조사·결정 제안)

- 한쪽이 만든 결과는 다른 쪽이 반드시 검증한다. 순서는 상황에 맞게 고른다.
  - Codex 가 먼저 구현·조사 → Claude Code 가 검증.
  - Claude Code 가 먼저 분석·구현 → Codex 가 읽기 전용으로 검증.
- 검증 항목: 변경 범위 (diff), 보호 파일 해시, 전체 unittest, 로직·근거, 문서 언어 검사 (`harness/rules/CHECK_LANGUAGE.py`, U+3002 없음), Secret·개인정보 미포함, `GROUP_SEND_APPROVED` 유지.
- 보고에는 두 쪽의 결론을 구분해 적고, 의견이 다르면 차이와 추천을 함께 적는다. 검증하지 않은 내용을 확인한 것처럼 쓰지 않는다.

## 3. 한쪽의 사용량 한도·지연

- 한쪽이 사용량 한도에 걸리거나 응답 없이 오래 걸리면 (기준: 1시간) 다른 쪽이 현재 저장소 상태에서 이어받아 진행한다. 처음부터 다시 하지 않는다.
- 이어받은 쪽의 결과는 한도가 풀린 쪽이 다시 검증한다. 둘 다 쓸 수 없으면 그 사실과 미검증 범위를 보고한다.
- 중단할 때는 해당 에이전트 프로세스만 멈추고 사용자가 연 다른 세션·관리 페이지는 건드리지 않는다.

## 4. 후속 프롬프트

- 모든 단계 (Claude Code 가 직접 한 단계 포함) 는 `harness/rules/NEXT_PROMPT_TEMPLATE.md` 형식의 후속 프롬프트로 끝낸다.
- 후속 프롬프트는 파일로 저장하지 않고 답변 본문에 보여 준다. 언어 검사와 U+3002 검사를 통과한 것만 제공한다.
- 사용자에게는 한국어로 보고한다.
