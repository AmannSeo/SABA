## 프롬프트 본문 양식

```
[작업 이름]
(한 줄)

[후속 프롬프트 종류]
A 다음 실행 / B 결정 및 계속 진행 / C 보완 / D 외부 조건 후 계속 진행 중 하나

[적용 규칙]
PROJECT_RULES.md, DEVELOPMENT_STATUS.md, harness/rules/Decisions.md 와
harness/ 아래 적용되는 규칙 파일을 모두 따른다.
작업을 시작하기 전에 현재 Repository 상태를 먼저 확인한다.

[현재 실제 상태]
- Branch / Worktree:
- 직전 실행의 종료 상태와 결과 요약:
- 완료된 작업:
- 미완료 작업:
- 실패 또는 미확인 사항:

[승인된 결정]
- harness/rules/Decisions.md 항목 ID 와 내용:

[미승인 사항]
- (승인되지 않아 실행하면 안 되는 것)

[이번 작업 목적]
-

[재사용 대상]
- (이미 있는 구현, 테스트, Fixture)

[허용 범위]
-

[제외 범위]
-

[변경 가능 영역]
-

[필요한 테스트]
- 테스트 항목:
- Mock 으로 검증할 것:
- 실제 연결로 검증할 것 (승인된 경우만):

[외부 연결 / 비용]
- 허용 여부와 범위:

[완료 조건]
- (진행률 작업 단위는 이 항목에서 가져온다)

[종료 규칙]
- 종료 후 A/B/C/D 종료 상태를 판단한다.
- 종료 상태에 맞는 후속 프롬프트를 작성하고 자체 검증한 뒤 제공한다.
- 후속 프롬프트 제공 후 STOP 하고, 사용자 승인 없이 다음 개발 작업을 실행하지 않는다.
```


## 종료 상태별 추가 항목

**B. 결정 및 계속 진행**

```
[결정이 필요한 항목]
각 항목마다:
- 무엇을 결정하는가
- 선택지, 각 장점과 단점
- 추천과 이유
- 결정이 다음 작업에 미치는 영향

[결정 후 진행]
- 사용자가 답하면 현재 Repository 상태에서 이어서 진행한다. 처음부터 다시 하지 않는다.
- 결정 내용을 harness/rules/Decisions.md 에 기록하도록 제안한다. (기록은 사용자 승인 후)
```

**C. 보완**

```
[실패 내용]
- 실패한 작업, 원인, 영향 범위

[수정 범위]
- 현재 승인 범위 안에서 수정할 항목
- 사용자 결정이 필요한 항목 (있으면 B 로 전환)

[재검증]
- 다시 실행할 테스트와 확인 항목
```

**D. 외부 조건 대기**

```
[막힌 조건]
- 필요한 권한, 서비스, 정보

[재개 전 확인]
- 조건이 해소되었는지 확인할 항목과 방법

[재개 조건]
- 어떤 상태가 되면 이어서 진행하는가
```
