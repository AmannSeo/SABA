# SABA 관리자 운영 문서

2026-10-16 사용자 결정: 파일럿 전에 로드맵 3단계 실행 파일 묶음·PC 이전 준비를 시작한다 (DECISIONS 기록 승인 대기, DEVELOPMENT_STATUS.md에 기록). 현재 절차는 docs/DEPLOY.md를 따른다. 새 PC는 Secret을 입력한 동일 Windows 계정으로 무인 실행하며 첫 자동 확인은 발송을 끈다. 정상 확인 후에만 사용자가 기존 PC 예약을 해제하고 새 PC의 발송을 켠다. 그룹 잠금·실제 파일럿 승인은 별개다. 이번 개발 작업은 기존 PC 관리 페이지·스케줄러를 바꾸지 않는다.

## 2026-10-14 작업 4 조사·연결 갱신

32개 Source를 설정했다. 신규 NIPA 사업공고·SMTECH R&D 관련 공지·KOCCA 공지사항·네이버 서치어드바이저 웹마스터 공지는 수집 방식 선택과 기존 최근 수집 표시 경로를 재사용한다. 추가된 Source는 실제 운영 수집 전까지 최근 수집 성공이 미확인이다. 이번 공개 페이지 HTTP 확인·Mock 검증을 운영 이력으로 기록하지 않았다. 본문·첨부 수집은 하지 않는다.

SMTECH 공지의 등록일과 수정일, NIPA 등록일과 신청기간을 구분한다. KOCCA 전체 지원공고는 동적 목록 검증이 남았으며 공지사항만 연결했다. 네이버는 공개 홈페이지에 게시된 웹마스터 공지만 읽고 일반 검색 블로그를 제외한다. 최근 공지가 오래됐으면 기존 7일 정책에 따라 게재 0건일 수 있다.

나머지 12곳과 인증키 대기 API 3곳·중앙노동위원회는 보류다. 상세 HTTP·robots·채널별 사유는 SABA_NEWS_SOURCES.md의 2026-10-14 표를 본다. API 어댑터를 만들거나 인증키를 입력·기록하지 않았다. 공개 페이지가 200이어도 제목·상세 URL·게시일 결합을 확인하지 못하면 활성화하지 않는다.

전체 상태: F0·F0-2·F1~F9 유지, F10 최근 수집 현황과 F11 주제별 부서 표시 유지, F12 부서 이름·기준 반영 유지, F13 일부 완료(32곳 설정, 조사 완료·보류 후보 남음), F14 항목별 필터 유지. 기사 단위 부서 관련 없음 피드백은 D-078에 따라 이월한다. 작업 5 로그인·권한·Secret은 다음 프롬프트의 설계·결정 대상이며 이번에 구현하지 않았다. 로드맵 2단계 전체 완료가 아니다.

이번 OpenAI·실제 --run·메일 발송·스케줄러 변경·실제 브라우저 화면 확인은 미실행이다. Claude Code의 후속 검증은 별도 실행 승인 범위를 확인한 뒤 수행한다. 네트워크가 열린 이번 조사 권한을 후속 실행의 비용·발송 승인으로 재사용하지 않는다.

최종 전체 회귀는 486개 중 485개 통과·1개 Skip, 실패·오류 0개다. 테스트에서는 외부 DNS·접속을 차단했으며 가상 응답을 실제 성공으로 보고하지 않는다. 운영·보호 자료 71개 파일은 시작 해시와 동일하다. 종료 B는 보류 후보와 작업 5 설계 결정이 남았다는 의미이며 이번 추가 조사·연결·회귀 실패를 뜻하지 않는다.

SABA(Security & AI Briefing Automation)를 운영하는 관리자를 위한 문서다.
현재 운영 방법(명령어 기준)과 향후 관리자 UI 도입 계획을 함께 기록한다.
결정 근거는 `harness/rules/DECISIONS.md` 의 D 번호를 따른다.

## 1. 전체 흐름

```
RSS 수집 → 같은 사건 묶음·선별 → AI 분석(요약·중요도) → AI 시사점·업무 연결
→ 메일 전용 HTML 생성 → 고정 TEST 수신자 발송
```

| 단계 | 담당 코드 | 저장 위치 |
|---|---|---|
| RSS 수집 | `python -m saba --collect-rss` | `data/saba.db` |
| 보호나라 공지 본문 | `src/saba/notice_body.py` | `data/boho_bodies.json` |
| AI 분석 | `src/saba/openai_adapter.py`, `src/saba/briefing.py` | `data/analysis.db` |
| AI 시사점·업무 연결 | `src/saba/insights.py` | `data/insights.db` |
| 메일 생성 | `src/saba/mail.py`, `templates/newsletter_mail.html` | `output/YY/MM/daily_YYYYMMDD_HHMM.eml` (2026-10-13 이전 파일도 2026-10-15 에 `output/26/10/` 으로 옮김, D-081) |
| 발송 | `src/saba/send_mail.py` | (발송 기록은 로그) |
| 매일 실행 | `src/saba/daily.py` | `logs/daily_YYYYMMDD.log` |

`data/`, `logs/`, `output/daily_*.eml`, `output/YY/MM/daily_*.eml` 은 Git 에 포함되지 않는다.

## 2. 자주 쓰는 명령

모든 명령은 프로젝트 폴더에서 프로젝트 Python 으로 실행한다.

```
.venv\Scripts\python.exe -m saba.daily --run          # 오늘 분량 실행 (수집 → 분석 → 메일 → 발송)
.venv\Scripts\python.exe -m saba.daily --run --no-send   # 메일 생성까지만 (발송 없음, D-071)
.venv\Scripts\python.exe -m saba.daily --register     # 작업 스케줄러 등록 명령 확인 (등록하지 않음)
.venv\Scripts\python.exe -m saba.daily --register --apply   # 작업 스케줄러에 실제 등록·갱신 (승인 후)
.venv\Scripts\python.exe -m saba.send_mail            # 발송 드라이런 (접속·발송 없음)
.venv\Scripts\python.exe -m saba.send_mail --send     # 최근 메일 .eml 을 TEST 수신자에게 1회 발송
.venv\Scripts\python.exe -m saba.admin                # 관리 컨트롤 페이지 시작 (브라우저가 열림, 11절)
.venv\Scripts\python.exe -m saba.admin --stop         # 관리 컨트롤 페이지 종료
.venv\Scripts\python.exe -m saba.deploy --backup      # data\·config\ 백업 zip (부서 PC 이전, docs/DEPLOY.md)
```

설치·이전·자동 실행 등록·제거는 `scripts\saba.ps1` 하나로 한다 (D-068, `docs/DEPLOY.md`).

작업 스케줄러 등록 상태 (2026-10-12 등록, D-063): 작업 이름 `SABA_Daily_Briefing`, 평일 08:00 + 최대 5분 지연.

작업 스케줄러 등록 상태 확인 (PowerShell):

```
Get-ScheduledTask -TaskName SABA_Daily_Briefing
```

## 3. 운영 설정 (`config/daily.json`, D-072)

관리 페이지 "예약 발송 설정" 화면에서 바꾸는 것을 기본으로 한다 (검증 → 저장 → 필요하면 작업 스케줄러 재등록 → 변경 기록).

| 항목 | 현재 값 | 설명 |
|---|---|---|
| `mode` | `weekly` | 반복: `daily` 매일, `weekly` 매주, `monthly` 매월, `dates` 특정 날짜 |
| `weekdays` | 월~금 | 매주일 때 요일 (MON~SUN) |
| `month_days` | 없음 | 매월일 때 날짜 (1~31, 그 달에 없는 날짜는 건너뜀) |
| `dates` | 없음 | 특정 날짜 (YYYY-MM-DD) |
| `time` | `08:00` | 발송 시각 (HH:MM) |
| `random_delay_minutes` | `5` | 최대 무작위 지연 0~30분 (0 이면 정각) |
| `max_analysis_calls` | `60` | 하루 AI 분석 신규 호출 상한 (0~60, 한국 날짜별 모든 실행 합계, D-077). 섹션 6개 × 10건이 하루 최대 필요량이다. 상한 때문에 분석하지 못한 글은 메일에서 뺀다 (D-080) |
| `max_insight_calls` | `30` | 하루 AI 시사점 신규 호출 상한 (0~60, 한국 날짜별 모든 실행 합계, D-077) |
| `send` | `true` | 예약 실행 때 발송 여부. `false` 면 메일만 만든다 ("지금 발송" 버튼은 항상 발송) |
| `log_days` | `90` | 실행 로그 보관 일수 (7~3650) |
| `mail_days` | `30` | 메일 파일 보관 일수 (1~3650) |

- 작업 스케줄러는 매일 같은 시각에 프로그램을 깨우고, 예약 날짜인지는 프로그램이 설정으로 판단한다. 예약일이 아니면 로그 없이 바로 끝난다.
- 반복·요일·날짜·시각·지연이 바뀌면 관리 페이지가 작업 스케줄러를 다시 등록한다 (켜짐·꺼짐 상태 유지, 실패하면 설정 원복). 호출 상한·발송 여부·보관 기간은 다음 실행부터 바로 적용된다.
- 변경 기록: `logs/settings_changes.log` (시각, 항목, 이전 값, 새 값, 재등록 여부). 관리 페이지 "실행 이력·로그 → 설정 변경 이력" 에서 본다.
- 파일을 직접 고친 경우에는 `--register --apply` 를 다시 실행해야 시각 변경이 반영된다.

## 4. 실패 처리 원칙 (D-061, D-062)

- 한 단계라도 실패하면 그날은 발송하지 않는다. 재시도하지 않는다.
- 수집 Source 일부가 실패하면 건너뛰고 나머지로 계속한다. 절반 이상 실패하면 그날은 발송하지 않는다 (D-078, 이전: 하나만 실패해도 발송하지 않음).
- 로그에는 단계, 건수, 오류 종류만 남긴다. 기사 내용과 Secret 은 남기지 않는다.
- 메일 발송 오류는 단계·오류 종류·SMTP 응답 코드·명령 응답 순서만 표시한다.

로그 예시 (`logs/daily_YYYYMMDD.log`):

```
INFO RSS 수집 완료
INFO 메일 생성 완료: daily_20261012.eml · 표시 3건 · 분석 재사용 0 · 신규 4 · 실패 0 · ...
INFO 발송 완료 1회: 받는 사람 1명 · 메시지 ... bytes · 포트 465 SSL/TLS · ...
```

## 7. 메일 (회사 메일: 한비로메일)

- SMTP: 포트 465, SSL/TLS, AUTH PLAIN (자동 인증 방식 선택은 서버 응답 어긋남으로 사용하지 않음, D-050)
- 보낸 사람·받는 사람: 서명 주소 1명으로 고정 (Cc·Bcc 금지)
- 한비로메일 웹메일 제약 (D-057 진단): script·style 블록 제거, 접기·펼치기 불가, 메일 안 이동 링크 불가, 외부 링크만 동작
- 그래서 메일은 780px table 레이아웃, 간략 보기만 표시, 버튼은 기사 원문 링크로 구성한다 (D-054~D-059)

### Secret (환경 변수, Windows 사용자 환경 변수)

| 이름 | 내용 |
|---|---|
| `OPENAI_API_KEY` | OpenAI API Key |
| `SABA_SMTP_HOST` | SMTP 서버명 |
| `SABA_SMTP_USER` | SMTP 아이디 (메일 주소의 @ 앞부분) |
| `SABA_SMTP_PASSWORD` | 웹메일 비밀번호 |
| `SABA_DATA_GO_KR_KEY` | 공공데이터포털 일반 인증키 (Decoding), 나라장터·K-Startup (발급 대기, D-078) |
| `SABA_LAW_OC` | 국가법령정보 공동활용 OC 값 (발급 대기, D-078) |

값은 코드·로그·문서·대화·Git 에 기록하지 않는다. 관리 페이지 설정 화면에서 관리자가 새 값을 입력해 바꿀 수 있다 (작업 5, 11절 로그인·권한·Secret). 바꾼 뒤 관리 페이지에서 시작하는 실행에는 바로, 작업 스케줄러는 다음 실행부터 적용되고, 이미 열려 있는 다른 프로그램 (VS Code 등) 은 다시 시작해야 반영된다.

## 8. 알려진 제한과 확인 사항

- 한비로메일 32일 미로그인 시 SMTP 비활성화 안내가 있다. 웹메일에 주기적으로 로그인한다.
- 작업 스케줄러는 이 PC 가 켜져 있어야 실행된다. 이 노트북 (S0 대기 모드) 은 절전 상태에서 예약 시각에 깨어나지 않거나 깨어난 직후 작업 시작이 거부 (0x800710E0) 되었다 (2026-10-14~16). TEST 운영 중에는 Windows 전원 설정을 "전원 연결 시 절전 안 함" 으로 두고 밤에 충전기를 연결한다 (2026-10-16 사용자 결정, 전원 설정은 사용자가 직접 변경).
- 중요도(긴급·중요·참고) 는 AI 판단이며 구체 등급 기준은 아직 정의되지 않았다.
- 부서별 업무 연결 대상: 경영전략팀, 기술개발연구소, 보안사업팀, STE본부 (STE본부 범위는 D-063 에서 사용자 제공).
- 작업 스케줄러 작업(SABA_Daily_Briefing) 은 사용자가 로그인해 있을 때만 실행된다.

## 9. 관리자 UI 도입 계획 (D-062, 구현은 별도 승인)

### 목적

SABA 의 주요 기능을 터미널 명령어 없이 관리한다.
관리자 UI 는 Core Pipeline 을 새로 구현하지 않고, 기존 Python 기능을 관리·제어한다.

### 기능 후보

**대시보드**
- 시스템 실행 상태, 자동 실행 ON/OFF, 마지막 실행 일시
- 최근 뉴스 수집 건수, AI 처리 성공·실패 건수
- 뉴스레터 생성 결과, 메일 발송 결과

**뉴스 및 AI 분석 관리**

2. 위 표의 정책·제한, 대상 그룹·첫 발송 시각·발신 계정·관찰 기간·회신 담당자를 확인하고 그룹 잠금 해제와 실제 파일럿 발송의 별도 승인을 받는다.
3. 승인된 작업에서만 `src/saba/send_mail.py`의 `GROUP_SEND_APPROVED` 값을 `True`로 변경하고 관리 페이지를 다시 시작한다. 파일럿 그룹을 발송 대상으로 선택해 확인한다. 이 문서 작업에서는 값을 바꾸지 않았다.
4. 승인된 회차에 첫 발송을 확인한다. 즉시 테스트 발송과 실제 파일럿 그룹 발송을 혼동하지 않는다. 오늘 발송 중복 방지를 우회하지 않으며 이미 실행 중이면 결과를 먼저 확인한다. 수신함 도착·표시·내용·주소 노출·크기·서버 제한을 수신자와 확인한다.
5. 발송 이력에서 회차·그룹·인원·수신자별 성공/실패/미시도/불명확을 확인한다. 성공은 SMTP 서버 수락이며 실제 도착 확인과 구분한다. 실패 재발송은 승인된 실패·미시도만 대상으로 확인 창을 거치고 원본 파일/해시·후손 회차를 확인한다. 성공·불명확·이미 재발송 성공한 대상에게 전체 재실행으로 중복 발송하지 않는다.
6. 합의한 며칠 동안 예약 실행·회신·수집 오류·호출 비용·발송 제한·재발송 결과를 관찰한다. 관찰 기간은 3~5영업일을 추천하되 회사와 사용자가 확정한다.
7. 합의한 정상 운영 기준과 관찰 결과를 근거로 사용자가 로드맵 2단계 완료를 판단한다. 예외·미확인·승인 대기를 남긴 채 완료로 표시하지 않는다. 부서 PC 이전과 전사 발송은 각각 후속 단계의 별도 승인이다.

되돌리기:

- 문제가 생기면 먼저 관리 화면 대시보드의 예약 발송 토글을 끄고 확인 창을 승인한다. 이는 `SABA_Daily_Briefing` 작업을 Disabled로 바꾸는 경로이며 꺼짐 상태를 확인한다. 화면이 실패하면 운영 담당자가 Windows 작업 스케줄러에서 해당 작업을 사용 안 함으로 설정하고 결과를 확인한다.

### 관리 컨트롤 페이지 범위 (1·2단계, D-070)

- 1단계 (운영 상태): 실행 상태·이력, 단계별 결과, 비용, 로그, 메일 미리보기, 기능별 테스트, 자동 실행 ON/OFF

- 공통 원칙: Secret 은 가려서 표시 (전체 값은 관리자 비밀번호 재확인 뒤 1분, D-084), 전체 발송은 승인 절차 없이 실행되지 않음, 모든 동작은 기존 명령과 같은 코드 경로 사용

### 로그인·권한·Secret (작업 5, 2026-10-14)

### 같은 사건 합치기 (2026-10-16)

- 묶기 단계 (D-027) 는 CVE 가 같을 때만 자동으로 묶는다. 보호나라처럼 제목만 있는 공지는 그 단계에서 CVE 가 보이지 않아 같은 취약점이 두 번 실릴 수 있었다 (Cisco Secure Email Gateway: 보호나라·CERT-EU).
- 분석 뒤 보안 분류 (보안 사고·취약점·권고·위협 동향) 끼리, 발행 3일 이내, 제목·요약·출처 제목에 같은 제품 영문 세 단어 (예: cisco secure email) 가 있으면 한 카드로 합치고 출처를 함께 보인다. 공식 출처를 대표로 둔다. 두 단어만 같으면 (예: cisco ios xe·xr) 합치지 않는다. 양쪽 모두 CVE 가 있는데 하나도 겹치지 않으면 같은 제품이라도 다른 취약점으로 보고 합치지 않는다. 한글 제품명은 아직 비교하지 않는다.

### 부서별 분류 기준 태그 화면 (2026-10-16)

- 설정 "부서별 분류 기준" 의 담당 업무·판단 예시를 태그로 보인다. 쉼표·문장 단위로 나누고 괄호 안 쉼표는 한 태그다. "…는 제외" 로 끝나는 회색 태그는 제외 조건이다. × 로 지우고 입력 후 Enter 로 추가하며 글자 수 (200·300자) 를 함께 보인다. 부서마다 태그 색이 다르다.
- "분야 (세부, 세부)" 처럼 괄호 안이 쉼표로 2개 이상 나뉜 항목은 점선 상자에 분야 제목 + 세부 태그로 보인다 (예: 경영·노무·세무 → 노동관계법 개정·노동 정책·노무 리스크, 연말정산·급여·원천징수·세무, 4대보험, 조직문화). 세부 태그를 하나씩 지우고 상자 안에서 더한다. 저장 문자열은 그대로라 AI 판단은 바뀌지 않는다 (AI 는 부서마다 "부서: 담당 업무 (예: 판단 예시)" 한 줄을 읽으므로 낱개로 나눠도 정보가 늘지 않고 분야 묶음이 오히려 맥락을 준다). 현재 기준 8개는 묶음으로 나눴다가 합쳐도 원문과 같음을 확인했다.
- 담당 업무는 부서가 하는 일 (넓은 분야), 판단 예시는 연결할 기사의 구체적인 모양과 제외할 기사 (회색) 다. 화면 표 위에 예시와 함께 설명한다.
- 공공 API 공고 키워드도 같은 태그 화면이다 (개수 표시). 저장 값과 형식은 이전과 같다 (쉼표로 이은 문장, 제외 조건 앞은 마침표). 현재 기준 8개는 태그로 나눴다가 다시 합쳐도 원문과 같음을 확인했다. 브라우저 스크립트가 꺼져 있으면 예전 입력칸이 보인다.

### Secret 보기·복사 (D-084, D-085 (5), 2026-10-16)

- 설정 화면 Secret 은 항목마다 카드 한 장이다. 카드 위에 이름 (복사 아이콘)·상태, 가운데 값 칸 (가린 값, 오른쪽에 보기·복사 아이콘), 아래에 수정·삭제 버튼이 있다. 값 칸 크기는 값 길이와 관계없이 같다.
- 로그인이 켜져 있고 관리자일 때만 값 칸에 앞 4글자와 가림이 보인다 (SABA_SMTP_PASSWORD 는 전부 가림). 보기 아이콘을 누르면 값을 가져와 보이고 아이콘이 다시 가리기로 바뀐다. 1분이 지나거나 새로 고치면 다시 가린다. 값은 칸 본문에만 두고 툴팁·속성에는 넣지 않는다. 복사 아이콘은 값을 화면에 보이지 않고 바로 복사한다. 비밀번호 재확인은 없다 (그 PC 의 Windows 사용자는 이미 같은 값을 읽을 수 있어 보호가 작음).
- 수정은 그 카드 안에 새 값 칸을 열어 저장하고, 삭제는 확인 창 뒤 사용자 환경 변수에서 지운다. 값이 없으면 입력 버튼만 있다. 보기·복사·변경·삭제한 이름과 사람만 설정 변경 이력에 남기고 값은 남기지 않는다. 조회자·로그인 꺼짐에서는 볼 수도 바꿀 수도 없다.

### 메일 서명 (2026-10-16)

- 설정 화면 "메일 서명" 에서 서명 HTML 을 붙여 넣거나 HTML 파일을 골라 저장한다. config/signature.html 에 저장되고 다음 메일부터 쓴다. 없으면 기본 서명 (templates/email_signature.html) 을 쓴다. "기본 서명으로 되돌리기" 로 지운다.
- 작성자 설정 값은 %%AUTHOR_TITLE%% (이름 직급)·%%AUTHOR_NAME%%·%%AUTHOR_TEAM%%·%%AUTHOR_DIVISION%%·%%AUTHOR_ENGLISH_NAME%%·%%AUTHOR_MOBILE%%·%%AUTHOR_EMAIL%% 로 넣는다. 회사 서명 이미지는 cid:saba-signature. 전체 HTML 문서면 style 과 body 안쪽만 쓴다.
- 작성자 값을 넣은 뒤의 결과도 다시 검사한다 (예: href 에 %%AUTHOR_NAME%%, 이름이 javascript:). 통과하지 못하면 기본 작성자로 채우고 경고 로그를 남긴다. CSS url() 안 이스케이프 (\6a 등) 도 막는다. 메일 보기 (/newsletter/view) 도 CSP sandbox 로 연다.
- 메일에 들어가는 부분 (style·body 안쪽) 에 script·iframe·frame·object·embed·form·svg·math·base·meta·link·applet 태그, javascript:·vbscript:·data:text/html 주소, on 이벤트 속성, CSS expression 이 있거나 10만 자를 넘으면 저장하지 않는다. 엔터티 (&#106; 등) 와 공백으로 나눠 쓴 모양도 풀어서 검사한다. head 의 meta charset 은 버려지므로 원본 서명 파일을 그대로 올려도 된다. 파일이 직접 고쳐져 깨졌으면 메일은 기본 서명으로 보내고 경고 로그를 남긴다. 미리보기는 스크립트 없는 sandbox 로 보이고, 미리보기 주소를 직접 열어도 CSP sandbox 머리글로 스크립트가 돌지 않는다. 변경 사실과 글자 수만 설정 변경 이력에 남긴다.

### 비밀번호 초기화 (2026-10-16)

- 관리자 비밀번호를 잊으면 SABA 가 설치된 PC 에서 `scripts\reset_password.cmd` (묶음에서는 "SABA 비밀번호 초기화.cmd") 또는 `scripts\saba.ps1 reset-password` 를 실행한다. 계정 목록에서 아이디를 고르고 새 비밀번호를 두 번 입력한다 (화면에 보이지 않음). 이 PC 의 Windows 로그인을 본인 확인으로 본다. 변경 사실만 설정 변경 이력에 남기고 비밀번호는 어디에도 남기지 않는다. 관리 페이지가 켜져 있으면 다시 시작한다.

### 기사·분석 (D-081, 2026-10-15)

- 메뉴 "기사·분석": 수집한 기사와 AI 분석 결과를 읽기 전용으로 본다. 기간 (최근 1·7·30일·전체, 기본 7일)·출처·분석 상태 (분석됨·대상 밖·분석 없음)·관련 부서 선택과 제목·요약·출처 검색, 25건 페이지.

### 공공데이터 API 수집 (D-078, 2026-10-14)

## 12. 사용자 피드백 작업 1 (2026-10-13)

작업 1~5는 모두 운영 로드맵 2단계(D-070) 안의 순서다. 작업 5(로그인·권한)까지 완료하기 전에 로드맵 3단계 패키지·부서 PC 이전을 시작하지 않는다.

### 관리 UI (F1~F5)

- 관리 화면의 모든 표에 공통 테두리·구분선·셀 간격·세로 중앙 정렬을 적용했다.
- 표 안 메일·로그·수신자별 결과·파일 링크도 기능 버튼과 같은 `btn` 모양이며 링크 동작은 유지한다. 메뉴·탭·본문의 일반 링크는 각각의 의미를 유지한다.
- 예약 발송 스케줄러가 꺼지면 예약 관련 표 대신 "예약 발송 꺼져 있습니다"를 표시한다. 상태 조회 실패는 꺼짐으로 단정하지 않고 "확인 불가"로 표시한다. 스케줄러 켜짐과 `send=false`(메일 생성만)는 다르다.
- 데스크톱 대시보드 우측에 "오늘 보내진 뉴스레터"를 배치했다. 좁은 폭에서는 아래로 쌓인다. 오늘의 실제 발송 기록에 연결된 메일을 사용하고, 최신 생성 파일을 발송본으로 대신 표시하지 않는다.
- 부분 발송·불명확·생성만·실패·파일 없음은 구분한다. 불명확한 실행에는 전체 실행을 다시 권하지 않고 발송 이력·받은 편지함 확인을 안내한다.
- F0에 따라 전후 캡처·다중 폭 캡처는 필수 검증에서 제외했다. 이전 기록의 4개 폭·전 화면 점검은 오래 걸린 원인 후보이며 실행 시간 증거가 없어 원인으로 확정하지 않는다.

### RSS 신뢰성 읽기 분석 (F10)

기준 실행: `2026-10-13T08:03:27+09:00` 자동 실행, 메일 생성 `2026-10-13T08:04:32+09:00`, `daily_20261013_0803.eml`.
운영 DB·로그·본문 캐시·기존 메일을 읽기 전용으로 읽었다. 실제 RSS·OpenAI·SMTP 접속이나 재생성은 하지 않았다.

현재 DB·현재 Source 설정으로 과거 실행 시각의 선정을 **재계산**했다. 당시 구성·변경 전 원문을 완전히 보존한 실행 스냅샷은 아니므로 과거 단계별 실측으로 주장하지 않는다.

- 현재 누적 기사 308개 중 해당 메일 생성 시각까지 최초 수집된 기사 306개. 이후 최초 수집 2개는 제외.
- 기간 안 157개, 기간 밖 149개. 같은 사건 묶음 후 155개 이슈(관련 기사 2개가 대표와 묶임).
- Source별 최대 5개에서 59개 이슈 제외, 국내·해외 각 최대 10개에서 76개 제외. 분석 대상 대표 이슈 20개.
- 생성 시각 이전 저장된 동일 입력 분석 20개, 대상 밖 11개, 동일 입력 분석 없음 0개. 대상 밖은 게재하지 않는다.
- 재계산한 게재 대표 9개 URL이 저장된 메일에 있고 심층 카드도 9개. 실제 실행 로그의 표시 9개와 일치한다.
- 선정 상한을 **AI 대상 밖 판단 전에** 적용하고, 대상 밖을 제외한 빈자리를 다른 후보로 다시 채우지 않는다. 따라서 Source가 많아도 20개 선별 후 9개만 게재될 수 있다. 보안뉴스 등 기간 안 기사도 지역 상한에서 먼저 제외될 수 있다.
- AI 실패·분석 없음이 항상 기사 제외를 뜻하지 않는다. 가상 데이터 테스트에서 분석 없는 기사는 유지하고 대상 밖만 제외하는 기존 동작을 검증한다.

## 13. 뉴스레터 목록과 실행 이력 관리 (작업 2, 2026-10-13)

뉴스레터는 기본 현재 연월로 열리며 전체 연도·전체 월 또는 다른 연월을 선택할 수 있다. 검색 대상은 파일명·종류·실행 주체이고 한 페이지에 25개를 표시한다. 연월은 기존 목록의 만든 시각(파일 수정 시각) 기준이다. 같은 시각의 파일은 파일명으로 정렬해 페이지 순서를 고정한다.

실행 이력은 날짜별 요약을 펼쳐 그 날짜의 모든 원래 실행을 확인한다. 연도·시작/종료 날짜·날짜/실행 주체/결과/메일명 검색을 지원하며 한 페이지에 날짜 묶음 25개를 표시한다. 검색에 맞는 실행이 하나라도 있는 날짜를 찾고 그 날짜의 상세에는 성공·실패·불명확을 포함한 전체 실행을 남긴다. 각 실행의 진행 단계·오류·메일·로그 링크와 발송 이력 탭의 회차·재발송 관계를 보존한다. 실제 로그·DB를 합치거나 수정하지 않는다.

필터 적용은 1페이지로 초기화하며 페이지 이동과 메일 선택 링크는 필터를 유지한다. 현재 달이 비었어도 다른 달을 선택할 수 있다. 실행 이력에서 목록 조건 밖의 메일을 직접 선택하면 안내와 함께 미리보기를 표시한다. 잘못된 파일명·없는 파일은 다른 파일로 몰래 대체하지 않는다. 잘못된 페이지·연월·기간·과도한 검색어는 안내 후 조정하며 읽기 실패는 오류 화면으로 남긴다.
